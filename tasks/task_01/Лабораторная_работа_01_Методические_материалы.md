# ЛР01. Методические материалы: приёмы и шаблоны

Справочник независимых примеров к лабораторной работе 1: healthcheck,
graceful shutdown, multi-stage Dockerfile, labels/метаданные, compose с
зависимостью, `.dockerignore`, базовая безопасность контейнера.

Это **не пошаговая инструкция** — адаптируйте примеры под свой вариант.
Теория — [лекция 01](../../curriculum/Лекция_01_Введение_в_распределенные_системы.md)
и [лекция 02](../../curriculum/Лекция_02_Контейнеры.md); задание и критерии —
[readme.md](./readme.md); собранный работающий эталон — [examples/](./examples/).

## Версии инструментов (проверено 09.08.2026)

* Docker Engine — ветка **29.x** (Docker Desktop содержит её); проверка: `docker version`.
* Docker Compose — **v2+** как плагин: команда `docker compose` (через пробел); дефисный `docker-compose` v1 давно мёртв.
* Канонический файл композиции — `compose.yaml`; поле `version:` в нём **устарело** и не нужно.
* Базовые образы примеров: `python:3.12-slim`, `node:22-alpine`, `redis:7-alpine`, `postgres:16-alpine`.
* `docker sbom` объявлен deprecated — используйте `docker scout sbom`.

## Подготовка (общие рекомендации)

* ПО: Docker Desktop, Git, редактор кода; при необходимости `curl.exe`, make.
* Проверка окружения: `docker version`, `docker compose version`, доступ к сети (pull образов).
* Структура проекта: `app/` (или `src/`) — исходники; `Dockerfile`, `.dockerignore`, `compose.yaml`, `README.md` с метаданными.
* Идентификаторы: slug — латиница `[a-z0-9-]`, lower-case, без пробелов; DNS-ограничение длины ≤ 63.
* Теги образов: не `latest`; по стандарту лабы — `:stu-<StudentID>-v<вариант>`.

## 1) Health-эндпоинты (разные стеки)

Python/FastAPI (основной стек курса) — health с проверкой зависимости:

```python
@app.get("/health")
async def health():
    try:
        await app.state.redis.ping()
    except Exception:
        raise HTTPException(status_code=503, detail="dependency unavailable")
    return {"status": "ok"}
```

Node/Express:

```js
app.get('/health', async (req, res) => {
  try { await redis.ping(); res.status(200).send('OK'); }
  catch { res.status(503).send('DEPENDENCY DOWN'); }
});
```

Go net/http:

```go
http.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) { fmt.Fprint(w, "OK") })
```

Health, который всегда отвечает 200, — бесполезен: он должен проверять
готовность обслуживать запросы (зависимость доступна).

## 2) Graceful shutdown

Node:

```js
const server = app.listen(port);
process.on('SIGTERM', () => {
  console.log('SIGTERM received, closing');
  server.close(() => process.exit(0));
});
```

Python/FastAPI — lifespan-хук (uvicorn сам обрабатывает SIGTERM):

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    log.info("start")
    yield
    await app.state.redis.aclose()
    log.info("graceful shutdown complete")
```

Go:

```go
srv := &http.Server{Addr: ":8080"}
go func() { _ = srv.ListenAndServe() }()
c := make(chan os.Signal, 1)
signal.Notify(c, syscall.SIGTERM)
<-c
_ = srv.Shutdown(context.Background())
```

Важно: процесс должен быть PID 1 и получать SIGTERM — используйте
**exec-форму** `CMD ["...", "..."]`, а не shell-форму `CMD команда`.

## 3) Multi-stage Dockerfile (паттерны)

Node.js 22:

```dockerfile
# syntax=docker/dockerfile:1
FROM node:22-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev

FROM node:22-alpine
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
USER 65532:65532
EXPOSE 8080
HEALTHCHECK --interval=15s --timeout=3s --retries=3 \
  CMD ["node", "-e", "fetch('http://127.0.0.1:8080/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"]
CMD ["node", "server.js"]
```

Python 3.12 — см. рабочий [examples/Dockerfile](./examples/Dockerfile).

Идеи оптимизации:

* слой зависимостей — до слоя кода (кэш);
* `slim`/`alpine`/distroless-базы, `.dockerignore`, без временных файлов;
* `pip --no-cache-dir` / `npm ci --omit=dev`;
* проверка размера: `docker images` (цель лабы — финальный ≤ 150 МБ);
* для Node.js `node:22-alpine` на диске уже близок к лимиту — уберите dev-зависимости целиком или возьмите distroless (`gcr.io/distroless/nodejs22-debian12`); для Python `python:3.12-alpine` даёт ~100 МБ (проверено эталоном).

## 4) Labels и метаданные

OCI-аннотации + метки студента (стандарт лабы):

```dockerfile
LABEL org.opencontainers.image.source="https://github.com/<you>/<repo>" \
      org.bstu.student.id="12345" \
      org.bstu.variant="47" \
      org.bstu.course="RSIOT"
```

Compose labels:

```yaml
services:
  app:
    labels:
      org.bstu.owner: "github-username"
      org.bstu.student.slug: "12345-v47"
```

Проверка: `docker inspect --format '{{json .Config.Labels}}' <image>`.

## 5) Compose с зависимостью и volume

`compose.yaml` (без `version:`); вариант с PostgreSQL:

```yaml
services:
  app:
    build: .
    image: smarthome-app:stu-12345-v47
    ports:
      - "8102:8080"
    environment:
      DATABASE_URL: postgresql://app:app@db:5432/app_12345_v47
      STU_ID: "12345"
      STU_VARIANT: "47"
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: app_12345_v47
    volumes:
      - data_w47:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app_12345_v47"]
      interval: 5s
      timeout: 3s
      retries: 5

volumes:
  data_w47: {}
```

Помните: `depends_on` без `condition` — только порядок **старта**, не
готовность; и даже с `service_healthy` зависимость может отвалиться позже —
сервис обязан переживать её недоступность (ретраи/503, лекция 01).

## 7) Базовая безопасность контейнера

* `USER` non-root (числовой UID); read-only root filesystem, если возможно.
* Не хранить секреты в `ENV`/`LABEL` Dockerfile — они остаются в образе.
* Явно объявлять порты; не использовать тег `latest` (кейс Trivy 03.2026: `latest` официального security-образа был перезаписан малварью; неизменяем только digest `sha256:...`).
* Скан образа: `docker scout cves <image>` или Trivy (сам Trivy ставьте по digest — ирония засчитана).

## 8) Именование и префиксы ключей

* Redis: `stu:<StudentID>:v<вариант>:<entity>` (например, `stu:12345:v47:readings:dev-42`).
* PostgreSQL: БД `app_<StudentID>_v<вариант>` или схема `<StudentID>_v<вариант>`.
* Имена ресурсов: `[a-z0-9-]`, ≤ 63 символа (DNS-ограничения — пригодится в лабе 2).
