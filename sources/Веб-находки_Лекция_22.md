## 1. Крючок: CrowdStrike 19.07.2024 — выкат на всех сразу

- Запрос: `CrowdStrike July 19 2024 outage 8.5 million Windows staged rollout canary deployment lessons`
- Источники:
  - [CrowdStrike: Falcon Content Update Preliminary Post Incident Report](https://www.crowdstrike.com/en-us/blog/falcon-content-update-preliminary-post-incident-report/)
  - [Security Boulevard: CrowdStrike Admits it Doesn't 'Canary' Test all Updates](https://securityboulevard.com/2024/07/crowdstrike-pir-canary-bsod-richixbw/)
  - [USENIX ;login: Consequences of Compliance](https://www.usenix.org/publications/loginonline/consequences-compliance-crowdstrike-outage-19-july-2024)

Факты: 19.07.2024 в 04:09 UTC CrowdStrike выпустил Rapid Response
Content-обновление сенсора Falcon; баг Content Validator пропустил
дефектный channel file 291 → out-of-bounds чтение → BSOD. Обновление
ушло **сразу на весь парк** — ни staged rollout, ни canary: **8,5 млн**
Windows-машин упали за минуты; аэропорты, больницы, банки; крупнейший
IT-сбой в истории (оценки ущерба — миллиарды долларов). Обещанные меры:
поэтапный выкат Rapid Response Content с canary-стадии, мониторинг и
сбор обратной связи для phased rollout.

## 3. Заблуждения: «CI с kubectl apply = GitOps»

- Запрос: `GitOps misconceptions push vs pull deployment CI/CD beginners mistakes kubectl apply pipeline`
- Источники:
  - [Akamai: Push vs. Pull-Based Architecture in GitOps](https://www.akamai.com/blog/developers/push-vs-pull-based-architecture-in-gitops)
  - [Unleash: GitOps vs. Traditional CI/CD](https://www.getunleash.io/blog/gitops-vs-traditional-ci-cd)
  - [Aviator: Choosing Between Pull vs. Push-Based GitOps](https://www.aviator.co/blog/choosing-between-pull-vs-push-based-gitops/)

Типичные заблуждения (→ дистракторы квизов и PI):

- «CI-пайплайн делает kubectl apply по мерджу — это и есть GitOps»:
  нет **непрерывной реконсиляции** — дрейф никто не замечает и не
  чинит; это push-модель, CI держит RW-доступ к кластеру (риск).
- Pull-модель: агент в кластере тянет состояние из git и постоянно
  сверяет; ручной kubectl apply/удалённый под — реконсиляция вернёт.
- «GitOps решает release management»: нет, GitOps решает деплой;
  стратегия выкатки — отдельный слой (Rollouts/Flagger).
- «Всё состояние кластера — в git»: борьба контроллеров и вечный
  Out of Sync.
