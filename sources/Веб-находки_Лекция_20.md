## 1. Крючок: сбой банка Monzo 27.10.2017 — Kubernetes + linkerd

- Запрос: `Monzo October 2017 outage postmortem Kubernetes linkerd etcd prepaid cards`
- Источники:
  - [InfoQ: Monzo Outage Post Mortem](https://www.infoq.com/news/2017/11/Monzo-Outage-Post-Mortem)
  - [The Register: Kubernetes bug bank app Monzo](https://www.theregister.com/2017/10/31/kubernetes_bug_bank_app_monzo/)
  - [Techerati: Lessons learned from Monzo's Kubernetes outage](https://www.techerati.com/the-stack-archive/cloud/2018/05/03/lessons-learned-from-monzos-kubernetes-outage/)

Факты: 27.10.2017 у британского цифрового банка Monzo встали платежи и
карты (~1,5 часа). Цепочка: за неделю до этого реконфигурация кластера +
четырёхмесячный баг Kubernetes → linkerd (сервис-меш первого поколения,
рулил маршрутизацией между микросервисами) перестал получать обновления
эндпоинтов и слал трафик на несуществующие IP. Реакция «перезапустить все
linkerd» вскрыла несовместимость версий K8s/linkerd — локальный сбой стал
полным отказом платформы. Публичный постмортем Monzo — классика жанра.

## 2. Актуальность: ландшафт сервис-мешей и Gateway API 2026

- Запрос: `Istio ambient mode sidecar-less 2026 status adoption Cilium eBPF service mesh landscape`
- Источники:
  - [reintech: Kubernetes Service Mesh Comparison 2026](https://reintech.io/blog/kubernetes-service-mesh-comparison-2026-istio-linkerd-cilium)
  - [DEV: Kubernetes Gateway API in 2026](https://dev.to/mechcloud_academy/kubernetes-gateway-api-in-2026-the-definitive-guide-to-envoy-gateway-istio-cilium-and-kong-2bkl)
  - [CORE SYSTEMS: Service Mesh — Istio, Cilium and the Future](https://core.cz/en/blog/2026/service-mesh-istio-cilium-2026/)

Факты 2026: ambient-режим Istio (без сайдкаров) — GA и рекомендуемая
модель для новых установок (прогноз: 50 %+ новых инсталляций к концу
2026); eBPF-датаплейны вытесняют сайдкары; Cilium — фактический стандарт
CNI, конвергенция CNI+mesh; снятие сайдкара убирает «двойной хоп» и
приближает задержку меша к голому металлу. Gateway API — стандартный
слой L7-маршрутизации, реализуют Envoy Gateway, Istio, Cilium, Kong.

## 3. Заблуждения: NetworkPolicy

- Запрос: `Kubernetes NetworkPolicy misconception default allow flat network beginners mistakes`
- Источники:
  - [kubernetes.io: Network Policies](https://kubernetes.io/docs/concepts/services-networking/network-policies/)
  - [DEV: NetworkPolicies — default-deny done right](https://dev.to/secopsloghq/kubernetes-networkpolicies-default-deny-done-right-293d)
  - [Cheveo: NetworkPolicy Cheatsheet](https://www.cheveo.de/en/blog/network-policies-cheatsheet)

Типичные заблуждения (→ дистракторы квизов и PI):

- «Kubernetes сегментирует сеть из коробки»: нет — плоская сеть,
  default allow: любой под достучится до любого.
- **«Применил NetworkPolicy — значит, она работает»**: политики
  исполняет CNI; часть CNI (включая дефолтные некоторых managed)
  **молча игнорируют** их — `kubectl apply` проходит без ошибок,
  enforcement нужно проверять тестом.
- «Политика действует только на то, что разрешила»: под, выбранный
  хоть одной политикой, переключается в deny-all кроме разрешённого;
  классика — забыть правило для DNS и «сломать всё».
