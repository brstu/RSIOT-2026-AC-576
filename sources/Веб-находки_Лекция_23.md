## 1. Крючок: сбой Cloudflare 18 ноября 2025

Изменение прав в базе ClickHouse заставило SQL-запрос, собирающий признаки
для модуля Bot Management, возвращать дубли строк — файл конфигурации
**вырос вдвое** и превысил зашитый лимит; прокси-слой на краю сети начал
падать с 5xx. Через edge-платформу Cloudflare идёт заметная доля мирового
веб-трафика, поэтому легли и «чужие» сервисы: X, ChatGPT, Discord и тысячи
сайтов. Отказали Workers KV (API-шлюз стоял за упавшим прокси) и Access
(аутентификация). Длительность — 5 часов 38 минут (11:28–17:06 UTC),
откат к заведомо хорошей версии файла — в 14:30 UTC. Урок для лекции:
edge — это тысячи точек присутствия, но управляющая плоскость и
конфигурация остаются глобальными → отказ распространяется на весь край
сразу.

## 2. Актуальность: холодные старты и цены FaaS (2026)

- AWS Lambda: оплата по запросам (~0,20 $ за миллион) + GB-мс исполнения;
  Node.js/Python — холодный старт обычно < 200 мс; для JVM решает
  **SnapStart** (восстановление из снапшота вместо полной инициализации),
  тарифицируется за хранение снапшота и за каждое восстановление, без
  наценки на сам вызов. Provisioned concurrency для чистого прогрева JVM
  рекомендуют заменять SnapStart.
- Edge-функции (V8-изоляты, Cloudflare Workers): старты единицы-десятки мс
  («эффективно нулевой» холодный старт), но окружение ограничено
  (не полный Node.js).
- Контейнеры со scale-to-zero (Cloud Run, Knative): холодный старт
  секунды.

## 3. Типичные заблуждения (→ дистракторы квизов и PI)

1. **«Serverless всегда дешевле»** — верно для рваного/редкого трафика
   (платишь только за использование), но при постоянной высокой нагрузке
   выделенный сервис/контейнер дешевле; надо считать, а не верить.
2. **«Холодный старт делает FaaS непригодным»** — устаревший страх:
   для Node/Python < 200 мс, у edge-изолятов — миллисекунды; но хвост p99
   критичных путей проверять обязательно.
3. **«Edge автоматически ускоряет всё»** — если функция на краю ходит в
   базу в одном регионе, география выигрыша не даёт: запрос всё равно
   летит через океан к данным.
4. **«Serverless = только функции»** — платформа шире: управляемые
   очереди, хранилища, шины событий; FaaS — лишь клей.
5. Когда serverless не подходит: WebSockets/долгоживущие соединения,
   длинные фоновые вычисления, жёсткие лимиты времени/памяти.
