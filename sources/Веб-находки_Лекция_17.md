## 1. Крючок: глобальный сбой Azure Front Door 29.10.2025

- Запрос: `Azure Front Door outage October 29 2025 configuration change Microsoft 365 down`
- Источники:
  - [ThousandEyes: Microsoft Azure Front Door Outage Analysis](https://www.thousandeyes.com/blog/microsoft-azure-front-door-outage-analysis-october-29-2025)
  - [Build5Nines: Major Azure Front Door Outage](https://build5nines.com/major-azure-front-door-outage-causing-widespread-service-disruptions-across-microsoft-365-microsoft-azure-and-the-azure-portal-october-29-2025/)
  - [Breached.Company: How a Configuration Error Cascaded](https://breached.company/microsofts-azure-front-door-outage-how-a-configuration-error-cascaded-into-global-service-disruption/)

Факты: 29.10.2025 с ~16:00 UTC ошибочное изменение конфигурации в
control plane Azure Front Door (глобальный L7-балансировщик и CDN
Microsoft) вызвало каскадный глобальный сбой: рост потерь пакетов,
HTTP-таймауты, DNS-аномалии. Легли или деградировали Microsoft 365,
Outlook, Teams (web), Xbox Live, Minecraft, Copilot, портал Azure и тысячи
клиентских сайтов; несколько часов недоступности. Меры Microsoft:
блокировка всех дальнейших изменений конфигурации AFD, откат на «last
known good», увод портала Azure с AFD, восстановление edge-узлов и
ребалансировка трафика. Случилось через 9 дней после сбоя AWS us-east-1
(лекция 1).

## 2. Актуальность: доля HTTP/3 в 2026

- Запрос: `HTTP/3 QUIC adoption percentage websites 2026`
- Источники:
  - [TechnologyChecker: HTTP protocol adoption 2026](https://technologychecker.io/blog/http-protocol-adoption)
  - [DEV: HTTP/3 Is at 35% Adoption](https://dev.to/linou518/http3-is-at-35-adoption-you-cant-call-quic-a-future-technology-anymore-2ghm)
  - [ISOC Pulse: Why HTTP/3 is Eating the World](https://pulse.internetsociety.org/blog/why-http-3-is-eating-the-world)

Факты: на 2026 год HTTP/3 — 21–39 % веб-трафика в зависимости от
методики (W3Techs ~30–39 % сайтов; Cloudflare ~35 % трафика своей сети;
по загрузкам страниц ~21 %). Среди топ-1000 сайтов — более 50 %
(Google, Meta, Netflix, Cloudflare давно перешли). Наибольшее
проникновение — mobile-first рынки (Италия, Бразилия, Индия ~29–30 %):
QUIC выигрывает на сетях с потерями.

## 3. Заблуждения: DNS «пропагация»

- Запрос: `DNS TTL misconceptions "propagation" myth caching resolvers`
- Источники:
  - [ProStack: Busting the myths of DNS Propagation](https://prostack.uk/blog/busting-the-myths-of-dns-propagation/)
  - [DNSLens: The DNS Propagation Myth](https://dnslens.app/blog/dns-propagation-myth-ttl-explained)
  - [ScoutDNS: DNS Caching and TTL](https://www.scoutdns.com/library/dns-caching-and-ttl/)

Типичные заблуждения (→ дистракторы квизов и PI):

- «DNS-изменения расходятся по миру 24–72 часа»: миф; DNS не
  «распространяется» рассылкой — записи тянутся по требованию и кэшируются;
  «пропагация» = истечение самой медленной кэшированной копии (TTL).
- «Понижу TTL одновременно со сменой IP — все переключатся мгновенно»:
  нет; старый TTL уже закэширован, снижать надо заранее.
- «Резолверы синхронизируются между собой»: нет; каждый резолвер кэширует
  независимо; некоторые принудительно держат минимальный срок кэша.
