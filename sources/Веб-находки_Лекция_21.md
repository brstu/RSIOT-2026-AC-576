## 1. Крючок: опечатка, положившая интернет — AWS S3, 28.02.2017

- Запрос: `AWS S3 outage February 28 2017 typo command postmortem removed servers`
- Источники:
  - [Официальный постмортем AWS](https://aws.amazon.com/message/41926)
  - [Gremlin: After the Retrospective — The 2017 Amazon S3 Outage](https://www.gremlin.com/blog/the-2017-amazon-s-3-outage)
  - [BleepingComputer: Command Input Typo Caused Massive AWS S3 Outage](https://www.bleepingcomputer.com/news/hardware/command-input-typo-caused-massive-aws-s3-outage/)

Факты: 28.02.2017 инженер S3 при отладке биллинга выполнил штатную
команду вывода серверов из ротации — **опечатка в одном параметре**
вывела гораздо больше серверов, чем нужно, включая критичные подсистемы
index/placement. S3 в us-east-1 лёг почти на 4 часа; легли GitHub,
Trello, Quora, Medium, Slack-вложения и т.д.; оценка ущерба индустрии —
~$150 млн. Подсистемы не перезапускались годами — рестарт шёл мучительно
долго. Ответ Amazon: добавить в инструмент **guardrails** (минимальная
скорость вывода, safety checks) и аудит похожих инструментов.

## 2. Актуальность: Terraform vs OpenTofu, 2026

- Запрос: `OpenTofu vs Terraform 2026 adoption BSL license fork status version`
- Источники:
  - [Encore: OpenTofu vs Terraform in 2026](https://encore.dev/articles/opentofu-vs-terraform-2026)
  - [Scalr: What Is OpenTofu? 2026 Guide](https://scalr.com/learning-center/what-is-opentofu)
  - [Jorijn: the fork finally diverged](https://jorijn.com/en/blog/opentofu-vs-terraform-2026-the-fork-finally-diverged/)

Факты: август 2023 — HashiCorp сменил лицензию Terraform с MPL 2.0 на
BSL 1.1; сообщество и вендоры форкнули Terraform 1.5 → **OpenTofu**
(Linux Foundation; CNCF sandbox с апреля 2025). 2025 — IBM купила
HashiCorp. Состояние 2026: OpenTofu ~12 % практиков (27 % планируют
оценку/расширение), версия 1.11.x; Terraform держит наибольшую долю.
Языки конфигурации совместимы; у OpenTofu — state encryption,
provider for_each, `-exclude`. Fidelity мигрировала 50 000+ state-файлов.
Вывод для курса: учим один язык (HCL) — умеем оба инструмента.

## 3. Заблуждения: state и drift

- Запрос: `Terraform state file misconceptions beginners edit manually delete drift mistakes`
- Источники:
  - [DEV: Terraform State Explained — why it breaks](https://dev.to/pandey-raghvendra/terraform-state-explained-what-it-is-how-it-works-and-why-it-breaks-1omp)
  - [Encore: Terraform Drift](https://encore.dev/articles/terraform-drift)
  - [HashiCorp: Manage resource drift](https://developer.hashicorp.com/terraform/tutorials/state/resource-drift)

Типичные заблуждения (→ дистракторы квизов и PI):

- «Ручная правка в консоли — быстро и безвредно»: это главный источник
  **drift**; при следующем apply Terraform приведёт ресурс к описанному
  в коде состоянию — ручная правка будет снесена (или ресурс пересоздан).
- «State — лишний файл, можно удалить/поправить руками»: state — единственная
  связь кода с реальными ресурсами; потеря = Terraform «забыл», чем
  управляет; правка руками — коррупция; для хирургии есть
  `state mv/rm`, `import`.
- «plan — формальность»: plan — это diff и главный инструмент ревью;
  `plan -refresh-only` — явная проверка дрейфа.
