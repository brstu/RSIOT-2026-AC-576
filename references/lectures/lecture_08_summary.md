# Лекция 08 — выжимка

**Тема:** партиционирование и балансировка: шардирование, consistent
hashing. Переплавлена из старой `Лекция_07_Партиционирование_и_балансировка.md`
(копия в `curriculum/archive_2025/`); излишки старого файла (гео, L4/L7 LB,
python-кольцо) ужаты в «Приложение: для любознательных».

## Ключевые концепции (введены здесь)

- Репликация — копии (чтения, отказоустойчивость), партиционирование —
  распил (объём, поток записи, параллелизм); в проде ножницы поверх
  ксерокса: каждый шард реплицирован. Аналогия пары — библиотека.
- Range-партиционирование: дешёвые сканы диапазона, но монотонный ключ
  (timestamp) = **горячий хвост** — 100 % записей в последнюю партицию.
- Hash: равномерность ценой смерти range-сканов; `hash % N` —
  катастрофа решардинга (при 3→4 узла переезжают 9 из 12 ключей).
- Consistent hashing: кольцо, ключ — первому узлу по часовой; переезд
  ~K/N (только дуга нового узла); vnodes выравнивают дуги (Cassandra
  снизила дефолт 256 → 16 — шарды не бесплатны).
- Горячий ключ («знаменитость»): хэш не размазывает популярность;
  лекарства — кэш, сплит (ключу не поможет), соль ценой scatter-gather.
- Индексы: локальный — платит читатель (scatter-gather, max по шардам),
  глобальный — писатель (две партиции, асинхронно → отстаёт; DynamoDB GSI).
- Ребалансировка: фиксированные партиции (Redis Cluster 16384 слота,
  Kafka) или автосплит (HBase/Mongo); фоново и с лимитом скорости.
- Карта «партиция → узел» — маленький критичный факт из лекции 07:
  живёт в etcd/ZooKeeper, роутер на watch; два владельца = split brain.
- «СмартДом»: ключ Reading — составной `(device_id, timestamp)`: хэш
  снаружи, время внутри; тот же ключ в Kafka (порядок только внутри
  партиции — трейлер л. 12). Балансировка данных ≠ балансировка
  запросов (LB — л. 17).
