## Ключевые концепции (введены здесь)

- Сетевой вызов ≠ локальный (CORBA/DCOM мертвы, Waldo 1994): третий исход
  «неизвестно»; **таймаут — не ответ «нет», а отсутствие ответа**.
- Синхронно (запрос-ответ, «звонок») vs асинхронно (сообщения,
  «мессенджер»); синхронность связывает судьбы по цепочке вызовов.
- REST: ресурсы/методы/JSON; анатомия `POST /readings` → `201 + Location`;
  идемпотентность методов — контракт: GET/PUT/DELETE — да, POST/PATCH — нет;
  коды: 4xx «чини запрос», 5xx «повторяй с умом», 429 особый.
- gRPC + Protobuf: `.proto`, номера полей на проводе, stream, HTTP/2
  (HTTP/3 экспериментален); «наружу REST, внутрь gRPC».
- Эволюция схем: обратная/прямая совместимость, добавлять необязательное,
  `reserved`, тип/смысл не менять; «схема — API во времени».
- Таймаут по p99; дедлайн едет по цепочке (deadline propagation).
- Ретраи: только 5xx/таймаут/429, экспоненциальный backoff + full jitter,
  потолок попыток, retry amplification (повторяет один слой).
- Ключ идемпотентности: генерирует клиент до 1-й попытки (Stripe), сервер
  хранит «ключ → ответ» (TTL ~24 ч, атомарно с эффектом); exactly-once
  delivery невозможна, at-least-once + дедупликация = exactly-once processing.
