## Ключевые концепции (введены здесь)

- **Событие ≠ команда**: факт в прошедшем времени, истинный навсегда,
  анонимный vs просьба конкретному исполнителю; антипаттерн «командное
  событие» (SendWelcomeEmailEvent); конверт: event_id, schema_version, ts.
- **Три топологии**: notification (тощее + обратный запрос = скрытая
  синхронность), event-carried state transfer (данные едут, копии
  стареют), event sourcing (хранение состояния ВНУТРИ сервиса).
- **Event sourcing**: append-only поток на агрегат; команда = загрузить →
  свернуть (fold) → проверить инварианты → дописать; оптимистичная
  блокировка по версии потока; возвращает «потерянное при UPDATE»:
  аудит, машина времени, вопросы к прошлому.
- **Проекция (read-модель)**: производная, пересоздаваемая реплеем (л. 12).
- **Снапшот** — кэш, не истина; **upcasting** / совместимость реестра
  для эволюции схем.
- **CQRS**: разделение ответственности write/read; мифы «= две БД» и
  «= eventual consistency» разоблачены (синхронная проекция возможна);
  polyglot-схема л. 10 = read-модели в масштабе системы.
- **UX итоговой согласованности**: «принято» вместо результата,
  optimistic UI, read-your-writes (трюк из л. 6).
- **Когда не надо**: CRUD-справочник — PostgreSQL; паттерн выбирается
  на сервис; между сервисами — события через outbox (л. 11).
