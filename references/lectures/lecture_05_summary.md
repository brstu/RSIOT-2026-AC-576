## Ключевые концепции (введены здесь)

- Два смысла C: инварианты ACID (лекция 11) ≠ согласованность реплик
  (наша). Аналогия пары — «меню обещаний» + групповой чат.
- CAP честно: C = линеаризуемость, A = ответ любой неотказавшей реплики;
  **P не выбирают** — выбор C-vs-A только во время разрыва.
- Критика: ярлыки CP/AP вредны (Kleppmann 2015) — определения узкие,
  single-leader+async ни CP, ни AP, гарантии живут на операциях;
  Brewer 2012 — «2 из 3» вводило в заблуждение, есть фаза восстановления.
- PACELC: else — latency vs consistency в целой сети; клетки PA/EL
  (Cassandra, DynamoDB), PC/EC (CockroachDB, Spanner), PA/EC (MongoDB).
- Спектр (лестница, Jepsen): линеаризуемость → sequential → causal →
  сессионные → bounded staleness → eventual; causal — сильнейшая,
  совместимая с доступностью при разрыве.
- Сессионные гарантии (Terry 1994): read-your-writes (правка Rule с
  телефона видна с планшета; сессия = пользователь), monotonic reads
  (график Reading не «мерцает» назад); токен версии, липкие чтения.
- Eventual = «сойдутся когда-нибудь, если записи прекратятся» — сроки
  не обещаны; правило пары — самая слабая достаточная модель
  (антипаттерн № 6).
- Ручки БД: DynamoDB ConsistentRead (2× цена), Cassandra ONE…QUORUM…ALL,
  MongoDB write/readConcern+readPreference, CockroachDB — без ручек.

## Студенты знают после

CAP/PACELC честно, линеаризуемость, sequential, causal, RYW, monotonic
