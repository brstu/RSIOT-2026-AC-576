## Ключевые концепции (введены здесь)

- **Dual write**: запись в две независимые системы не делается атомарной
  никаким try/catch — процесс смертен между записями; перестановка
  порядка меняет тип ошибки, не устраняет её.
- **2PC**: prepare (локи + голос + журнал намерения) → commit/abort;
  цена — блокировки через сеть, **in-doubt** (участник не имеет права
  решить сам), координатор-SPOF. Внутри одного контура — можно; между
  микросервисами — антипаттерн по умолчанию; брокеры prepare не умеют.
- **Saga**: цепочка локальных транзакций + компенсация на каждый шаг;
  компенсации выполняются в обратном порядке; компенсация ≠ rollback
  (необратимое не отзовёшь). Пример: подписка pending → списание →
  правила → active.
- **Хореография** (события, без центра, логика размазана) vs
  **оркестрация** (Temporal/Camunda, логика в одном месте); правило:
  2–3 линейных шага — хореография, ветвистое — оркестрация.
- **Изоляции у саги нет**: промежуточные статусы видимы; приёмы —
  семантические статусы, необратимое в конец цепочки, компенсации
  проектировать заранее.
- **Transactional outbox**: бизнес-строка + событие в одной локальной
  ACID-транзакции; relay (poller c FOR UPDATE SKIP LOCKED или CDC
  Debezium) публикует с **at-least-once**.
- **Идемпотентный потребитель / inbox**: дедупликация по event_id
  (`ON CONFLICT DO NOTHING`) в одной транзакции с обработкой;
  exactly-once обработка = at-least-once + идемпотентность.
- **Дерево выбора**: не делить → outbox (80 %) → saga → 2PC (осознанно).

## Слоты

- **Крючок:** Commercial Bank of Ethiopia 15.03.2024 — 3 часа рассинхрона
  выдачи наличных и учёта остатков: ~490 000 транзакций, ~8 млн долларов
  «из воздуха» — `sources/Веб-находки_Лекция_11.md`.
- **Квиз-извлечение:** по л. 10 (вокрлады, LSM, wide-column vs columnar,
  копии в polyglot).
- **PI:** как не потерять SubscriptionCreated; верный C (outbox);
  дистракторы: publish до коммита (ложное событие), после коммита с
  try/catch (dual write), 2PC с брокером.
- **Живой сеанс:** outbox на PostgreSQL: DDL → транзакция с двумя
  INSERT → poller (SKIP LOCKED) → убиваем relay между publish и UPDATE →
  дубль → вывод «не потеряем — outbox, не задвоим — потребитель».
- **Мост:** лаба 4 (стриминг, tasks/task_04, после л. 13) — конвейер
  outbox→брокер→идемпотентный потребитель на практике; проверить лабы
  1–3 на «commit + отправка»; лабы 5–6 — поды убивают штатно.
