# Лекция 06 — выжимка

**Тема:** репликация: лидерная, мульти-лидерная, кворумы. Переплавлена из
старой `Лекция_05_Репликация_и_консенсус_обзор.md` (копия в

## Ключевые концепции (введены здесь)

- Три причины реплицировать: доступность, задержка, масштаб чтений;
  асимметрия — чтения масштабируются копиями, записи нужны на каждой.
- Лидерная репликация: WAL/лог изменений (append-only, позиции) даёт
  порядок и измеримый лаг; PG шлёт сам WAL, MySQL — отдельный binlog.
- Лестница долговечности `synchronous_commit` (PG 17/18): off → local →
  remote_write → on → remote_apply; кворумная запись `ANY N (...)`;
  «подтверждено ≠ сохранено» при async (Redis WAIT — то же честно).
- Sync не бесплатен: RTT в каждой записи + блокировка при смерти
  sync-реплики; semi-sync понижает доступность записи; слоты репликации
  раздувают диск (PG 18: idle_replication_slot_timeout).
- Лаг ломает сессионные гарантии (RYW, monotonic reads, prefix — связка
  с л. 05); лекарства: чтение с лидера, липкая сессия, токен версии (LSN).
- Фейловер: три ловушки — «мёртв или медленный», потерянный хвост WAL,
  split brain; фенсинг эпохами/term, lease, pg_rewind обрезает хвост.
- Мульти-лидер: мульти-регион, офлайн, Hub с локальной автономией;
  конфликты: LWW (теряет, л. 04) / версионные векторы / CRDT обзорно.
- Безлидерная: N/W/R, W+R>N — пересечение; read repair, анти-энтропия
  (Меркл), hinted handoff; sloppy quorum ломает пересечение; кворум ≠
  линеаризуемость (записи «в полёте», нет отката частичных записей).
- Выбор схемы по потоку данных: Reading — безлидерная; Rule — лидер +
  токен версии (+мульти-лидер для Hub); реле/Alert — лидер + ANY 1 + фенсинг.
