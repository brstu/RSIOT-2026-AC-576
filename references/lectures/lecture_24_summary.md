## Ключевые концепции (введены здесь)

- Мониторинг (known unknowns: заранее заданные проверки) vs
  наблюдаемость (unknown unknowns: диагностика новых вопросов по богатой
  телеметрии); нужны оба.
- Три сигнала = три вопроса: метрики — «что/насколько плохо», трейсы —
  «где в цепочке», логи — «почему именно». Стек: /metrics → Prometheus
  (pull; up==0 при падении цели) → Grafana + Alertmanager; Loki (логи),
  Tempo (трейсы).
- Метрики: counter (только rate()!), gauge, histogram (перцентили из
  корзин). Именование snake_case + единица. **Кардинальность**: каждая
  комбинация меток = временной ряд; ограниченные словари в метках,
  идентификаторы — в логи/трейсы.
- Логи: JSON с ts/level/service/env/**traceId**; корреляция с трейсами;
  без секретов/PII, без debug в проде.
- Трейсы: span/trace, контекст в заголовках, ASCII-пример дерева span'ов
  (push-провайдер съел 3,79 с); семплирование 1–10 % + ошибки/медленные.
- OpenTelemetry: SDK + OTLP + Collector; 2026 — graduated CNCF, № 2 по
  контрибьюторам, traces/metrics/logs GA, profiles alpha; лекарство от
  vendor lock-in. Пример NodeSDK-инициализации (до импорта приложения).
- SLO → **бюджет ошибок** (валюта: есть — катим релизы, сгорел — морозим
  фичи) → **burn rate** (во сколько раз быстрее нормы сгорает бюджет);
  алерт с двумя окнами (1 ч + 5 мин), порог 14,4 = 2 % бюджета/час,
  `for: 2m`. Alert fatigue и почему naive-алерты плохи.
- Blameless постмортем: чинится система, а не человек (у Datadog —
  автообновление, снёсшее сеть, а не «виноватый инженер»).
