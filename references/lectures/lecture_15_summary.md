## Ключевые концепции (введены здесь)

- **Главный тезис**: микросервисы — стратегия масштабирования
  ОРГАНИЗАЦИИ (независимый деплой команд, закон Конвея), оплачиваемая
  сетью; систему они не ускоряют.
- **Границы по bounded context** (не по слоям, не по техническим
  шагам); «Device» биллинга ≠ «Device» телеметрии — норма. **Тест
  автономии**: релиз без согласований? один владелец? данные свои?
- **Database-per-service**: общая БД = скрытые контракты на схему,
  связанные релизы; общие данные — через события (л. 11–13).
- **Контракты**: OpenAPI/реестр схем (машиночитаемо, не вики);
  совместимая эволюция (optional — да, rename — /v2); contract-тесты
  (Pact) в CI. Продолжение schema-on-write (л. 10).
- **Sync vs async**: синхронно — критичный путь; цепочка 5 × 99,9 % ≈
  99,5 %; здоровый профиль — короткий sync-край + событийная задняя
  шина; длинные sync-цепочки — запах.
- **API Gateway** (TLS, auth, rate limit — token bucket л. 9,
  маршрутизация; без бизнес-логики) и **BFF** (агрегирующий слой на
  витрину — лекарство от chatty).
- **Discovery** (Consul, etcd/Raft л. 7, DNS K8s) и **health checks**:
  liveness (перезапуск) ≠ readiness (не слать трафик); слитые — вред.
- **Анти-паттерны**: распределённый монолит, границы по шагам
  (диагноз Prime Video: + данные через S3), общая БД, nanoservices,
  chatty. **Модульный монолит** — честный старт малой команды.

## Примеры «СмартДома»

Сервисы: устройства, телеметрия, правила/тревоги, уведомления,
пользователи, биллинг; BFF мобильного приложения (показания + тревоги +
подписка одним ответом); копия контактов у уведомлений.
