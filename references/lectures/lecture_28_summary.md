## Ключевые концепции (введены здесь)

- **Зона поражения (blast radius)**: узел → AZ → регион → **аккаунт**
  → провайдер; аккаунт — единая зона (кейс UniSuper).
- **RPO / RTO / RTA**: допустимая потеря данных / целевое время
  восстановления / факт с учений (~60 % узнают RTA > RTO на первом
  тесте). Не «RPO/RTO системы», а по классам сервисов.
- **Лестница DR**: backup&restore → pilot light → warm standby →
  active-active; ступень выбирается ценой простоя, не престижем;
  active-active = конфликты записи (л. 6) + двойной счёт (л. 27).
- Бэкапы: **3-2-1** (+иммутабельность; «1» вне зоны поражения — урок
  UniSuper); **репликация ≠ бэкап** (DROP TABLE/ransomware едут во все
  регионы); непроверенный бэкап ≠ бэкап (ключи KMS!); регулярный тест
  восстановления.
- Мульти-регион: внутри региона синхронно (multi-AZ, RPO≈0), между —
  асинхронно (физика + CAP; лаг = RPO); failover: DNS TTL/GSLB (л. 17),
  кворум + арбитр в третьей локации против **split-brain** (л. 6–7);
  stateful — часто полуавтомат; data residency (л. 25) и egress (л. 27).
- Учения: runbook «для дежурного в 3 ночи», game days (старший брат
  chaos, л. 9), замер RTA, blameless (л. 24); ~48 % инцидентов ДЦ —
  процедуры/люди.
- **Финальный кейс** (живой сеанс): «СмартДом» от SLO до DR-плана за
  5 шагов — требования (л. 1/24/26) → архитектура (Hub-правило л. 23,
  K8s+HPA, очередь, шардированная БД, mTLS, GitOps+canary,
  burn-rate-алерты, «цена дома») → DR-классы (тревоги active-active /
  приём warm / история pilot light / отчёты backup) → 3-2-1 с копией у
  другого провайдера, Hub = «нулевой регион» → проверка (k6, chaos,
  ежеквартальные учения). Пойнт: ни одной новой технологии — решения в
  правильном порядке.
- Карта курса: блоки A (физика РС) / B (данные в движении) /
  C (платформа) / D (эксплуатация) — «не 28 тем, а один способ думать».
