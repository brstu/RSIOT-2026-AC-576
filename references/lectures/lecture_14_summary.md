## Ключевые концепции (введены здесь)

- **Два мира**: batch (полно, но отложенно, дёшево) vs streaming
  (секунды, «по состоянию на сейчас», дороже); критерий — какую
  задержку терпит потребитель результата.
- **Идемпотентный batch**: единица работы — партиция по дате (ключ
  идемпотентности), атомарная перезапись выхода, `--date` вместо
  `now()` → безопасный перезапуск и **backfill**; оркестраторы
  (cron → Airflow).
- **Стрим-процессор**: stateless (консюмер лабы 4) vs stateful (окна,
  джойны); движки: Kafka Streams (библиотека), Flink (2.0 — март 2025,
  первый мажор за 9 лет), Spark (микробатчи).
- **Два времени**: event time (ts конверта) vs processing time;
  расходятся штатно (Hub досылает буфер); агрегация по processing time
  искажает два окна на каждое опоздание.
- **Окна**: tumbling (встык), sliding (перекрытие), session (по паузе).
- **Watermark** = max(event time) − допуск; допуск — по p99 опозданий;
  политика поздних: allowed lateness (поправка) → side output
  (batch-досчёт) → осознанное отбрасывание с метрикой. Ручка
  «задержка ↔ полнота» = PACELC в аналитике.
- **Чекпоинты**: состояние + offset'ы атомарно; рестарт = чекпоинт +
  реплей; «exactly-once» = чекпоинты + транзакционные sink'и,
  кончается на внешних эффектах (SMS — ваша идемпотентность).
- **Lambda** (поток + batch-истина, логика дважды) vs **Kappa**
  (только поток + реплей журнала новой версией).
