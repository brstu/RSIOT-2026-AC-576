**Тема:** отказоустойчивость: таймауты, ретраи, circuit breaker,
изоляция, backpressure, error budget, chaos engineering. Сырьё — старая
лекция 08 (ужата с 1297 строк) + chaos-часть старой 25; написана как новая.
Файл: `curriculum/Лекция_09_Отказоустойчивость_и_chaos_engineering.md`.

## Ключевые концепции (введены здесь)

- **Каскадный отказ**: локальная авария распространяется через разделяемые
  ресурсы (пулы/потоки), растущие очереди и неограниченные ретраи; каскад —
  эмерджентное свойство, «никто не ошибся».
- **Бюджет таймаутов**: connect/read/total; таймауты в цепочке убывают
  сверху вниз (5→4→3→2→1 с); deadline propagation (дедлайн едет в запросе).
- **Ретраи всерьёз**: повторять только transient (обрыв/таймаут/502/504);
  429/503 + Retry-After — ждать; ретраить у краёв (амплификация 3×3×3=27);
  retry budget (повторы ≤ 10 % трафика) вместо «3 раза каждому».
- **Circuit breaker**: CLOSED → OPEN (fail fast) → HALF-OPEN; свой breaker
  на зависимость; медленные ответы — тоже ошибки; мини-реализация Python
  ~20 строк в тексте.
- **Изоляция**: bulkhead (пулы по зависимостям), rate limiting (token
  bucket → 429 + Retry-After), blast radius (зоны, канарейка), N+1/N+2.
- **Backpressure/load shedding**: миф «буфер побольше»; ограниченная
  очередь + сигнал (429, окно TCP) или сброс по приоритету (телеметрию
  можно, Alert никогда); Retry-After = backpressure до клиента.
- **Error budget**: (1−SLO)×N; burn rate = факт/допустимое (пример: 0,4 %
  при SLO 99,9 % → burn rate 4 → бюджет за 7,5 дней); алерты multi-window.
- **Грациозная деградация**: лестница fallback (панель → кэш → только
  тревоги → read-only), код заранее за feature-флагами.
- **Chaos engineering**: канон steady state → гипотеза → мин. blast
  radius → впрыск с откатом → чинить и повторять; tc netem; обзорно
  Chaos Mesh, LitmusChaos (CNCF), Gremlin, Pumba.
