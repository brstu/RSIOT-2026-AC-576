# Лекция 23 — выжимка

**Тема:** serverless и edge computing. Написана с нуля (в сетке 2025 темы
не было); файл — `curriculum/Лекция_23_Serverless_и_edge_computing.md`.

## Ключевые концепции (введены здесь)

- Лестница абстракций «кто чем управляет»: IaaS → managed K8s → PaaS →
  FaaS; serverless = серверы есть, но их не видно вам; аналогия
  «личная машина → каршеринг → такси».
- FaaS: функция — обработчик события, не «маленький сервер». Триггеры:
  объект в хранилище, очередь, таймер, HTTP. Следствия: нет состояния
  между вызовами, лимит времени (Lambda — 15 мин), параллелизм давит
  на пул соединений БД. Доставка «как минимум один раз» → идемпотентность.
- Scale to zero; холодный старт: конвейер (машина → окружение → рантайм →
  инициализация); цифры 2026: Node/Python < 200 мс, JVM — секунды,
  V8-изоляты — мс, контейнеры scale-to-zero — секунды. Лечение: тонкий
  пакет, SnapStart (снапшот памяти), provisioned concurrency (оплата
  простоя!), архитектура (критичный путь мимо холодной функции). Мерить p99.
- Экономика: цена = вызовы (~0,2 $/млн) + ГБ-с. Сценарий А (фото по
  движению, 100 тыс/сут) ≈ 5 $/мес — FaaS выигрывает; сценарий Б
  (телеметрия 500 запр/с 24/7, 1,3 млрд вызовов/мес) ≈ 500+ $ против
  десятков за контейнеры. Правило: рваное/редкое → FaaS, ровное/плотное →
  контейнеры.
- Serverless шире FaaS: управляемые кубики (S3, DynamoDB, SQS,
  EventBridge, API GW), функции — клей. Ограничения: WebSocket, долгие
  вычисления, vendor lock-in (обвязка, не код); Knative/OpenFaaS.
- Edge: свет в оптике ~200 000 км/с, Брест→Сингапур ≥ 85 мс RTT;
  V8-изоляты; edge ускоряет только то, чьи данные тоже на краю
  (Workers KV/D1 — eventual consistency). Асимметрия: дата-плоскость
  распределена, управляющая плоскость едина (→ глобальные отказы).
- Hub «СмартДома» = edge: критичное правило «дым → сирена» исполняется
  локально — «мы не ускорили функцию, мы убрали её с критичного пути».
