# Лаба 04 — выжимка

**Тема:** очереди и стриминг — телеметрия «СмартДома» через брокер
(Kafka; NATS — бонус). Написана с нуля по новой сетке 8 лаб
(старое Observability-содержимое task_04 — в `archive_2025/task_04` и
`task_08`). **Лекции-основы: 12–13.** Каталог: `tasks/task_04/`.

## Состав

- `readme.md` — задание с метками artifacts/criteria/bonuses,
  правила защиты/пересдачи (85 %), 10 контрольных вопросов.
- `Макет_отчета.md` — титул БрГТУ, части 0–5, таблица критериев,
  разделы «Зачем это в реальных системах» и «Использование ИИ»
  (заполняет студент), контрольные вопросы.
- `Варианты.md` — 25 вариантов (подсистемы датчиков: дым, протечка,
  CO2, движение, розетки, котёл, бассейн…) + вариант 0 (термостаты) =
  examples; у каждого поле payload, правило тревоги, нагрузка для
  расчёта партиций (норма консюмера 20 000 соб./с — из лекции 12).
- `QUICK_START.md` — Kafka за 10 минут + таблица частых проблем.
- `examples/` (вариант 0): `docker-compose.yml` (apache/kafka:4.0.0,
  KRaft, одна нода), `producer.py` (ключ device_id, acks=all,
  идемпотентный продюсер, лог партиция/offset), `consumer.py` (группа
  rule-engine, ручной коммит ПОСЛЕ обработки, дедупликация по event_id
  в SQLite в одной транзакции с эффектом, DLQ после 3 попыток, флаг
  `--crash-before-commit` для эксперимента с дублем).

## Задание (структура и баллы)

Часть 0 — быстрый успех ≈30 мин (compose up, топик, консольные
утилиты). 1 — проектирование топика/конверта (15). 2 — продюсер (20).
3 — консюмер-группа + эксперимент масштабирования (20). 4 — главный
эксперимент: поймать дубль при падении до коммита → идемпотентность
«до/после» (25). 5 — DLQ для ядовитого сообщения (15). Документация
(5). Бонусы (+15): NATS JetStream (+5), JSON Schema (+4),
transactional outbox (+4), Kafka UI лаг (+2).
